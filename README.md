# AI Challenge Roof

Чат-клиент с агентом, который отвечает на вопросы по документации проекта
[`vitchuk/ai-challenge-mcptools`](https://github.com/vitchuk/ai-challenge-mcptools),
используя локальную RAG-базу знаний.

## Что умеет

- **Вкладка «Ассистент»** — чат с агентом. Список чатов (история в SQLite), вейтер из трёх
  точек во время ожидания, время ответа у каждого сообщения.
- **Команда `/help <вопрос>`** — ответ строится по RAG-базе, с цитатами и панелью
  источников. При вводе `/` появляется автокомплит команд.
- **Инструменты GitHub MCP** — агент через function calling умеет получать текущую ветку,
  список ветвей и дерево файлов репозитория. Если вопрос про файлы/ветки, агент обязан
  вызвать инструмент, а в сообщении показывается свёрнутый блок «Вызовы MCP (N)».
- **Вкладка «Настройки»** — статус RAG-индекса, Ollama, DeepSeek и GitHub MCP; описание
  индексации и стратегии поиска; настройка `Top_K` (по умолчанию 4); кнопка переиндексации;
  карточка «Репозиторий» (текущая ветка, ветви, дерево файлов).

## Как это работает

1. **Индексация (стратегия `fixed`).** Документы читаются из GitHub через GitHub MCP
   (`get_file_contents`): `README.md`, `AGENTS.md` и все `docs/*.md` верхнего уровня.
   Ветка определяется динамически (ветка по умолчанию репозитория, см. ниже).
   Текст режется скользящим окном по предложениям: целевой размер 500–1000 «токенов»
   (≈3 символа/токен), перекрытие 150. Каждый фрагмент получает имя файла и заголовок,
   затем эмбеддится локальной моделью `qwen3-embedding:0.6b` (Ollama). Нормализованные
   векторы сохраняются в `server/data/rag/fixed/index.json`.
2. **Поиск (Query Rewrite).** Вопрос переписывается моделью DeepSeek в самодостаточный
   запрос (с учётом истории; при ошибке используется исходный вопрос) → поиск по косинусной
   близости → берутся ровно `Top_K` фрагментов → только они передаются модели для ответа.
3. **Ответ.** Модель отвечает только по контексту, приводит дословные цитаты и раздел
   «Источники:». В интерфейсе идентификаторы фрагментов скрыты.
4. **Агент и GitHub MCP.** Модели передаётся белый список инструментов MCP
   (`get_repository_tree`, `get_file_contents`, `list_branches`, `list_commits`) вместе с
   координатами репозитория и текущей веткой. Для вопросов о файлах/ветках/коммитах вызов
   инструмента принуждается (`tool_choice="required"` на первой итерации, с fallback на `auto`).
   Текущая ветка определяется через `search_repositories` (поле `default_branch`), дерево
   файлов — `get_repository_tree` (recursive), ветви — `list_branches`, граф ветвей
   (Mermaid `gitGraph`) — по последним коммитам каждой ветви. Результаты рендерятся в
   сообщении (дерево — библиотекой `@grapoza/vue-tree`, граф — Mermaid).

## Требования

- Windows, Python 3.11+ (доступен через `py`)
- Node.js 18+ и npm
- [Ollama](https://ollama.com) с моделью `qwen3-embedding:0.6b` (`ollama pull qwen3-embedding:0.6b`)
- GitHub PAT в `.env` (`GITHUB_PERSONAL_ACCESS_TOKEN`)
- Ключ DeepSeek в `.env` (`DEEPSEEK_API_KEY`)

## Запуск

```bat
copy .env.example .env
rem заполните DEEPSEEK_API_KEY и GITHUB_PERSONAL_ACCESS_TOKEN
start.bat
```

`start.bat` создаёт виртуальное окружение, ставит зависимости, скачивает GitHub MCP Server
(`setup_mcp.ps1`, версия закреплена и проверяется по sha256) и запускает бэкенд и клиент.

- клиент в dev-режиме: http://127.0.0.1:5173
- бэкенд: http://127.0.0.1:8000 (в prod-режиме отдаёт собранный клиент из `client/dist`)

## Структура

```
server/app/        config, llm, rag, rag_pipeline, mcp_client, indexer, chat_store, chat, api, main
server/config.json параметры RAG, LLM, MCP, целевой репозиторий
client/            Vue 3 + Vite + TypeScript + Tailwind
scripts/dev.py     одновременный запуск бэкенда и Vite
```
